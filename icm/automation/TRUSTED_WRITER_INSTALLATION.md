Keep a dated record with operator, Windows build, Codex/app version, exact integrated broker commit and hashes, commands, exit results, and redacted screenshots. Use canary files and disposable repositories. Never print or probe real secret contents.

2. **Select distinct identities and storage.** Record real SIDs for founder/operator, request-only trigger, trusted broker and restricted worker. A proposed layout is `C:\ProgramData\SchoolDashboardTrusted\bin` (pinned broker, read/execute by broker), `...\authority` (founder-approved grant and installation binding, founder write, broker read), `...\state` (broker write for journal/lock, founder recovery access), and `C:\SchoolDashboardWorker\<task-id>` (worker write, broker inspect). Broker startup must verify its installed code, binding provenance, protected directory ownership/ACLs, grant revision/hash and checkout/branch allowlist. The repository module's `codeSha256` field is a schema check only; it is **not** installed code attestation. Any failure stops before a worker. Preserve the previous pinned version for rollback. 4. **Create a narrow trigger interface.** An actual Scheduled task may only make a request with a broker-generated idempotency key. It may not choose grant path, task ID, repository, command, risk, operation or permission. The trusted service/broker reads its own protected binding and current grant. Enforce request deduplication and rate bounds outside the model. Verify duplicate requests do not consume multiple task slots. If native Scheduled cannot run with a request-only identity and with GitHub write plugin unavailable, native mode is `BLOCKED`; do not substitute a permissive prompt.
5. **Configure the worker host.** Install a pinned CLI under the restricted worker identity with its own profile and authentication lifecycle. Use explicit argv, cwd and finite timeout. The fixture adapter shows the argument and output contract; it cannot prove Windows sandbox, token, connector or descendant-process isolation. Use a Windows Job Object or equally strong process-tree lease so cancellation/crash cannot free the broker lock while descendants write. Withhold real worker activation until this is observed. ## Pause, revoke, recovery and rollback

- **Immediate pause:** founder stops/disables the trigger and changes the protected grant's `paused` or `revoked` state through the authenticated owner path. Broker must re-read it before spawn and each risky transition; terminate/wait for the job tree and retain the lock until child death is proven. Revocation cannot undo effects already completed; journal/report must state them.
- **Crash recovery:** disable new requests, inspect process tree and lock ownership under the broker identity, grant revision, journal integrity, workspace Git status, exact PR head and hosted checks. A stale lock is never stolen by timestamp/PID guess. Preserve dirty work. If any source conflicts, stop and escalate; do not reset, rebase or discard. Resume the same task only after independent reconstruction.
- **Disable/remove:** founder disables the Scheduled task, revokes the grant and publisher credential, waits for worker tree termination, exports redacted journal evidence, then removes only the reviewed installation paths using the original owner identity. Restore previous Codex settings from the recorded backup; verify shared GitHub plugin permissions did not change unexpectedly. Roll back installed broker to the previous pinned build only after grant/schema compatibility review. No auto-reenable.

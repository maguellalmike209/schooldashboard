# School Dashboard — Current Implementation

SD-001 established the Next.js application foundation. SD-002 added the read-only shell and navigation. SD-003 added the Courses overview and reusable Course Cards. SD-004 added course-specific current-week and material context to Course Page. SD-005 added the Weekly Plan, shared authored plan fixture, and cross-view weekly progress. SD-006 added the actionable Today view and Dashboard daily plan. SD-007 added Upcoming Assignment context and completed Milestone 1 integration. The project uses npm with `package.json` and `package-lock.json`; the verified direct framework versions are Next.js 16.3.6, React 19.3.0, TypeScript 6.0.3, and Tailwind CSS 4.3.3. No dependency was added for SD-002 through SD-007.

The App Router lives in `src/app/`. The root layout provides School Dashboard identity, a responsive sidebar/mobile header, four primary links, and one main region. The small client component `src/components/primary-navigation.tsx` marks the active link from the pathname; Courses remains active on a Course Page. `globals.css` imports Tailwind CSS. Root configuration includes TypeScript, ESLint, and PostCSS. `next.config.ts` disables Next.js agent-rule generation so development commands preserve the repository's existing `AGENTS.md`.

The implemented routes are `/` (Dashboard), `/courses`, `/courses/[courseId]`, `/weekly-plan`, and `/today`. Dashboard is the root view. Courses lists the shared static courses as linked Course Cards; Dashboard reuses compact versions. Known course IDs show matching identity and scoped context and plan items. Unknown course IDs return a clear 404. Weekly Plan is a dedicated course-grouped view of objectives, relevant assignments, and dated Study Tasks. Today is a dedicated actionable view derived from incomplete Study Tasks planned for the fixed reference date. Course Page is reached through course selection, not a top-level nav item.

`src/lib/academic-context.ts` is the shared static source for Fall Quarter 2026, fixed reference date September 25, 2026, academic week September 21–27, 2026, PHY 009D / Modern Physics, and date-only Lecture #02 on September 25. It also contains lightweight fictional WRT 101 / Academic Writing and HIS 110 / World History courses. The lecture is Course schedule context without a supplied time or room, not a timed Class Meeting. The shared fixture has three authored Learning Objectives, three Assignments, and seven authored Study Tasks: PHY 2 of 5 complete, WRT 1 of 2, HIS zero tasks, and overall 3 of 7. Study Task dates, completion, optional duration, and Objective/Assignment relationships remain static; weekly selections, progress counts, and upcoming deadlines are derived. PHY Problem #1 is due September 28 while its linked Study Task is planned September 25. WRT's response draft is a fictional Course obligation due September 27. HIS's fictional Map quiz is due on the reference date without a linked Study Task.

Course Page filters static week context, materials, current-week Objectives, Study Tasks, and upcoming Assignments by Course ID. PHY 009D shows the source-supported course beginning, scheduled Lecture #02 topics, and assigned textbook as reference context. WRT 101 and HIS 110 have no supplied week topics or materials and display explicit missing-context states. The same authored Study Task IDs and completion states appear in Weekly Plan and Course Page; `StudyTaskList` displays planned date, completion, supplied duration, and relevant relationships without mutation controls. Dashboard, Course Cards, Course Page, and Weekly Plan use the same task-count progress helper. Today and Dashboard share a derived selection of incomplete reference-day Study Tasks in authored order; Dashboard Next Action is the first such task. TodayTaskList resolves Course, Objective, and linked Assignment context from canonical IDs without inventing a missing duration. AssignmentList presents due-date context on Dashboard, Course Page, and Weekly Plan from the same fixture, ordered by due date and authored order. An Assignment deadline does not create or reorder a Study Task. No persistence, authentication, AI, or integrations are implemented.

From the repository root, use Node.js 20.9 or later and npm:

| Command | Purpose |
| --- | --- |
| `npm ci` | Install dependencies from the lockfile. |
| `npm run dev` | Serve the development app at `http://localhost:3000`. |
| `npm run lint` | Run ESLint. |
| `npm run typecheck` | Generate Next.js route types, then run TypeScript without emitting files. |
| `npm run build` | Create the production build. |
| `npm run start` | Serve the production build after `npm run build`. |

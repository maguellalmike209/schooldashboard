# M3 installed-host proof runbook — future owner-controlled action

**No installed-host test was authorized or executed by this shadow phase.** This runbook is a reviewable procedure for a later founder-approved host test, not an installation script.

1. Identify the intended Windows machine/build and the actual founder, trigger, broker, worker and publisher SIDs. Have an administrator create separate disposable canary directories under the operating system's temporary directory, each with a `SYNTHETIC_CANARY.json` marker containing `{"kind":"SYNTHETIC_CANARY","disposable":true}`. Put no real grant, token, key, `.env`, private student data or original source in them.
2. Outside the restricted worker, record ACLs and hashes for dummy owner-grant, broker-state, canonical-checkout and worker-workspace canaries. Admin setup of identities, ACLs or connector policy requires a separately authorized change; this M3 run does not perform it.
3. Under each **actual intended SID**, run `node scripts/icm-next/m3-cli.mjs inventory` and, only on an explicitly named disposable canary, `node scripts/icm-next/m3-cli.mjs probe --canary <path> --identity <observed SID>`. Save redacted stdout, command exit, SID and source SHA. Denials must be OS-backed; a model refusal or broken CLI is UNKNOWN. Confirm worker workspace allow and protected canary denies with read, create, rename and delete attempts.
4. Test native Scheduled trigger's real identity and installed connector permissions independently. It must be request-only and unable to edit source, grants, broker, journal, credentials or GitHub. If native Scheduled cannot be restricted, keep it disabled and evaluate an alternate trigger in a separately approved phase.
5. On a disposable workspace, use two independent fake workers to test exclusive lease, parent death with surviving descendant, cancellation and revocation. Keep the lock held whenever descendant death is uncertain. Actual Job Object/process-tree containment remains a separately authorized installed-host test.
6. An owner/admin should inspect applicable protected-main rulesets, required reviews, stale-review dismissal, bypass actors, force-push/deletion settings and who may edit workflows. Record exact API responses or screenshots redacted of account secrets. A 403 or summary `protected: true` leaves G5 UNKNOWN.
7. Map each observation to G1–G8 with source version, time, SID, negative result, reviewer and limitations. Only independent actual-host proof may change a gate to PASS. Remove disposable canaries through the owner-approved cleanup procedure after evidence is saved. Do not use this runbook to enable a real writer or M5 cutover.
